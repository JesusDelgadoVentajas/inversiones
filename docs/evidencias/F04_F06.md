# Evidencia F04–F06

**Fecha:** 2026-10-02. **Entorno:** Node 24.21.0, Wrangler 4.145.0, Vitest 4.1.11, D1 local y Workerd local. No se autenticó Cloudflare, no se desplegó, no se crearon bases remotas y no se consultaron proveedores financieros en esta entrega.

## F04: contratos y D1

- `app/shared/contracts/`: UUID persistentes distintos de símbolo/nombre, emisor y cotización, mapeos exclusivos, decimal exacto, unidad de cotización y factor a moneda mayor, fecha civil, UTC, procedencia, estados y motivos. Esquemas de cotización, barras, hechos, métricas, noticias, eventos, comparables, capacidades y preferencias.
- Fixtures sintéticos aceptados/rechazados: importe mayor de `Number.MAX_SAFE_INTEGER`, GBX/GBP, cero frente a ausencia, día bisiesto, offset no UTC, periodo invertido, barra con máximo incoherente, cuerpo sin procedencia y mapeo de dos entidades. La suite usa `test:contracts`.
- `app/migrations/0001_core.sql` crea las ocho tablas del plan con claves, índices y restricciones. 0002 añade metadato de uso de caché; 0003 limita plazas por proveedor; 0004 identifica el origen de la caché para revocar retención por fuente. `test:migrations` aplica 0001 en D1 local efímera, inserta empresa/listing/caché sintéticos, aplica las siguientes versiones, comprueba conservación de datos y rechazos por unicidad, FK, mapeo ambiguo y JSON inválido. El estado temporal se elimina al terminar.
- [API.md](../API.md) distingue rutas ya activas de las futuras y documenta formatos, límites, errores y fechas. La API financiera prevista sigue sin implementarse ni prometerse como disponible.

## F05: implementación local de acceso

- `worker/auth/access.ts` toma `Cf-Access-Jwt-Assertion`, restringe el dominio JWKS a Cloudflare Access, verifica firma RS256, emisor, audiencia, `exp`, `nbf`, `iat`, tipo `app` y correo exacto del propietario. `jose` guarda claves públicas temporalmente y puede recargarlas al rotar; un error o variable ausente deniega acceso.
- Pruebas Workerd con claves sintéticas: token válido, expirado, aún no válido, alterado, audiencia, emisor y correo ajenos, token sin correo, tipo de token incorrecto y dos claves durante rotación. Una prueba de la ruta `/api/v1/capabilities` simula la respuesta JWKS y comprueba que un token válido recibe `APP_NOT_READY`; las rutas sin configuración reciben `ACCESS_NOT_CONFIGURED`.
- Staging/producción compilan con `APP_READY=false`, `ALLOW_LIVE_PROVIDERS=false` y sin D1 remota. La [guía](../DESPLIEGUE.md) registra lo que exige una cuenta real. Las pruebas anteriores **no** verifican política Access, hostnames, sesión móvil, secretos reales o CPU de la cuenta Free.

## F06: capa común sintética

- Interfaces opcionales para búsqueda, precio, histórico, cuentas, noticias, eventos y comparables; ningún adaptador comercial instalado.
- Transporte: HTTPS y origen aprobado, sin redirecciones, 8 s por defecto, máximo de respuesta, JSON y esquema validados. 401, 403, 429, `Retry-After`, timeout, JSON inválido y tamaño excesivo se convierten en códigos seguros sin exponer cuerpo/cabeceras privadas.
- D1: reservas de cuota por ventanas en una transacción; una restricción hace rollback si una ventana se agota. Asignación 50 % producción, 15 % staging, 5 % pruebas manuales y 30 % reserva, redondeada hacia abajo. Una prueba con límite sintético de 20 solicitudes agota cada partición y comprueba que la suma más la reserva sigue siendo 20. Hasta tres plazas simultáneas por proveedor con vencimiento y liberación por propietario. Una nueva solicitud se deniega si falla D1.
- Caché: clave SHA-256 que incluye proveedor, capacidad, entidad, divisa, feed, resolución, ajuste, periodo y versión. Solo conserva resultados si hay permiso explícito de retención, con TTL menor entre la licencia y la política por bloque. Mantiene `checkedAt` y `observedAt` originales, marca resultados antiguos, agrupa solicitudes iguales dentro de una instancia y usa leases D1 entre instancias. Limpieza por lotes de caducados, contenido y proveedor revocado, con objetivo interno de 80 MB de contenido, sin afirmar que el tamaño total físico de D1 sea idéntico.
- Orquestador: cada intento, incluido el único reintento transitorio, reserva presupuesto; 403/429 no se reintentan; un circuito temporal corta fallos repetidos. La traza incluye solo `requestId`, proveedor, capacidad, estado, intentos y duración. Pruebas concurrentes comprobaron que se respetan el límite de cuota y las plazas; ninguna llamada real consumió plan de datos.

## Validación final

- Exportación del índice Git a una carpeta temporal sin dependencias instaladas: `npm ci` terminó correctamente con 0 vulnerabilidades notificadas. En esa copia, `npm run check` pasó `typecheck`, `lint`, 8 pruebas de la sonda previa, 15 de contratos y 23 de integración (46 en total), la migración D1 desde vacío y desde `0001`, la comprobación de configuración, las dos compilaciones y el escaneo de 86 archivos versionables y 7 compilados. Después se añadió la prueba de cuota compartida sintética: la validación final del árbol de trabajo pasó 47 pruebas (8 + 15 + 24).
- El servidor local devolvió 200 para la portada y los dos endpoints de salud, 200 para el ejemplo explícitamente sintético, 503 `ACCESS_NOT_CONFIGURED` para una ruta privada sin configuración y 404 JSON para una ruta API desconocida. Las migraciones `0001`–`0004` también se aplicaron con Wrangler a D1 local.
- Wrangler advierte que el binding D1 raíz no se hereda en staging/producción. Es intencional: las dos configuraciones remotas tienen `d1_databases: []` hasta crear y verificar bases separadas. La comprobación del artefacto confirma que no se incluyó un binding remoto ni se activaron datos reales.
- La revisión de enlaces locales y `git diff --check` se completó al cerrar la entrega. Los artefactos, fixtures y resultados versionados no incluyen credenciales ni respuestas financieras externas.

**Pendiente para aceptar F05/F06:** cuenta Cloudflare y acceso protegido comprobados; límites y licencias de proveedores en F02; prueba de un adaptador real aprobado, cuota contractual compartida entre entornos reales y alternativa legal de la misma calidad. Las funciones genéricas sin una fuente real no cierran G-DATOS.
